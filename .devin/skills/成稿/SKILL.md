驱动 `novel/<书名>/` 走完本仓库的成稿管线（`shared/生产流程.md` 的 G0–G5 门）。本 skill 只做调度与定位；各阶段规程在对应 skill 里，标准以 `shared/生产流程.md`、`shared/审读规范.md`、`shared/写作规范.md` 为准。

## 定位（先执行）

1. 读 `novel/<书名>/章节设计.md` 末尾的章节状态表；目录不存在则从立项开始。
2. 对照定位表确定当前阶段：

| 现状 | 所处阶段 |
|---|---|
| `novel/<书名>/` 不存在或骨架未齐 | 立项 |
| 状态表有"未写"章 | 初稿 |
| 全部"初稿"但有章低于分级字数下限 | 扩写 |
| 字数全达标但未全"定稿" | 审读 |
| 全部"定稿"且无 tag `<书名>-v1.0` | 结稿 |

3. `git worktree list` 确认工作区。惯例：worktree `../physics-<书名>`，分支 `<书名>-初稿`。

## 执行

按 立项 → 初稿 → 扩写 → 审读 → 结稿 顺序，逐阶段按其 skill 规程执行（/立项、/初稿、/扩写、/审读、/结稿）。

## 停止点

- 默认每过一个阶段门停下报告，等用户确认再继续。
- 用户明说"跑到底""定稿后推送"时连贯执行至结稿，中途不停。
- 硬停两种情况：① 需作者裁决的事项（书名、结局、关键机制）——列选项问作者，不得自定；② 同一评审阶段满 5 轮仍有 P0——停笔，与作者定方向。
